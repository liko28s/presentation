Agents without supervisionAgentes sin supervisión

Fig 2. Start with the slider on "No human check". The cart is the agent: goal, plan, act (tools), observe, and again, lap after lap. Nobody watches. The gauge in the middle is drift: small errors the agent cannot see in its own work. Nothing visibly breaks, the needle just climbs into the red. Now slide to "every 3 laps", then "every lap": the gate stops the cart, a human checks, drift resets to zero. The price is speed, the loop is slower. That is the trade: control costs time. This is real, not a toy: Dex Horthy (HumanLayer) spent about six months telling teams not to read the code, then walked it back after systems had to be rebuilt. Voss also notes OpenAI says humans may review PRs but are not required to. The model is illustrative: one unit of drift per lap, relative units, not measurements.

Raise Review (internal test from level 2): the bottleneck moves to Test, then Deliver. Each fix exposes the next bottleneck: Goldratt's theory of constraints, as Voss uses it. The facts behind the figure. One: agents multiply code output, shipped software rises far less (NBER working paper 35275, "Writing Code vs. Shipping Code"; press summaries disagree on which tool and metric gave 741%, so say "much more code, far less shipped"). Two: human review loses accuracy fast. The SmartBear/Cisco study (2006) found best defect detection under about 300 lines per hour and recommends reviews under 200 to 400 lines. At 450 lines per hour a 10,000-line diff is about 22 hours of reading. Three: machines already review. GitHub says Copilot code review is now more than one in five reviews on GitHub. Voss adds that four AI reviewers each found real bugs, but different ones. Illustrative model, not measurements.
